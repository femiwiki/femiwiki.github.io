11월 9일 23시 12분부터 10일 0시 15분까지 1시간 3분 동안 페미위키가 차트를 새로 그리지 못했고, 문서 정보에서 구글 애널리틱스의 조회수를 가져오지 못했습니다. 이미 그려 둔 문서와 차트는 그대로 보였고 오류 응답도 없었습니다. 이 동안 차트 4개가 든 문서 하나가 차트 없이 그려졌고, 문서 정보 요청 9건이 조회수를 받지 못했습니다. 미디어위키 컨테이너가 IAM Roles Anywhere로 자기 AWS 역할의 자격 증명을 받도록 바꾸면서 세션을 1시간으로 받았는데, AWS는 세션보다 오래 가는 토큰을 내주지 않습니다. 세션을 2시간으로 받도록 고쳐 다시 배포했습니다.

원인

페미위키는 두 가지 바깥 서비스에 AWS STS가 발급한 토큰으로 자신을 증명합니다. 차트를 그리는 Lambda는 페미위키의 역할이 발급받은 토큰만 받고, PageViewInfoGA는 같은 방식으로 받은 토큰을 구글 애널리틱스의 자격 증명과 바꿉니다. 두 스크립트 모두 1시간 동안 유효한 토큰을 요청하고, 컨테이너가 뜰 때와 그 뒤 15분마다 새로 받습니다.[1]

192번째 세대부터 미디어위키 컨테이너는 서버의 역할 대신 IAM Roles Anywhere로 받은 mediawiki 역할의 세션을 썼습니다. 이 세션은 1시간짜리였습니다.[2] STS는 남은 세션 시간보다 오래 가는 토큰을 발급하지 않으므로, 막 받은 세션에서도 1시간짜리 토큰 요청은 모두 SessionDurationEscalationException으로 거절되었습니다. 서버의 역할로 받던 때에는 이 제한에 걸리지 않았습니다.

컨테이너는 토큰을 받지 못해도 뜨도록 되어 있어,[3] 배포는 성공으로 끝났습니다. 배포 전에 Roles Anywhere 세션으로 토큰을 받아 보는 시험을 했지만 5분짜리 토큰으로 했기 때문에 이 제한이 드러나지 않았습니다.

처음 고친 infra#1642는 Roles Anywhere 프로필과 역할의 세션 한도만 2시간으로 올렸습니다. 세션을 받는 도구(aws_signing_helper)는 따로 지정하지 않으면 한도와 상관없이 1시간 세션을 요청해서,[4] 적용한 뒤에도 토큰 요청은 계속 실패했습니다. 도구가 2시간을 요청하게 한 docker-mediawiki#1842가 배포된 뒤에야 토큰이 나왔습니다.

이용자가 겪은 것

차트는 문서를 새로 그릴 때만 렌더러에 요청하므로, 이미 그려 둔 문서의 차트는 그대로 보였습니다. 이 동안 차트를 새로 그리려다 실패한 것은 23시 35분 10초에 구글 주소에서 온 요청이 대한민국 성매수 통계 문서를 새로 그리게 했을 때의 차트 4개뿐입니다. 그 뒤 193번째 세대 배포 전까지 이 문서를 서버에 다시 요청한 이용자는 없었고, CloudFront가 이때 그린 판을 다른 이용자에게 보냈는지는 기록이 없어 알지 못합니다. 지금은 차트 4개가 모두 그려집니다.

문서 정보(action=info) 요청은 이 동안 58건이었고, 그 가운데 9건이 구글 애널리틱스에 조회수를 물으려다 토큰이 없어 실패했습니다. 이 문서들의 문서 정보에는 조회수가 나오지 않았고, 실패한 문서는 30분 동안 다시 묻지 않습니다. 나머지 49건은 구글 애널리틱스에 묻지 않았는데, 앞서 받아 둔 수치를 보였는지는 로그로 가릴 수 없습니다. 잡 러너에서도 같은 이유로 조회수를 받지 못한 작업이 8건 있었습니다.

실패한 토큰 요청은 CloudTrail에서, 차트와 조회수의 실패는 Grafana Cloud Loki의 fastcgi-192와 잡 러너 로그에서, 요청한 주소는 웹 서버 접근 로그(http-192)에서 센 것입니다.

복구가 늦어진 까닭

첫 수정이 원인의 절반만 고쳐 40분 가까이 지나서야 두 번째 수정을 열었습니다. #1842가 든 이미지는 23시 52분에 준비됐지만, 이 배포에 확장 기능 이미지 범프와 보안 헤더 수정을 함께 묶고 그보다 앞서 기다리던 infra PR 두 건을 먼저 머지하느라 193번째 세대 배포는 0시 12분에 시작했습니다.

그 사이 이미지 범프 봇이 연 infra#1640은 192번째 세대가 배포되기 전의 main에서 만들어져 이미 떠 있는 192번째 세대를 다시 만들려 했고, 다시 올린 뒤에는 #1842가 없는 이미지를 담고 있었습니다. 승인 대기 중인 이 실행을 승인하지 않고 닫았습니다. 고치는 동안 12개 저장소에 CI 설정 PR이 한꺼번에 열려 있어 수정의 검사가 러너를 기다렸습니다. infra#1642의 머지 단계는 러너를 3분 45초 기다렸고, docker-mediawiki#1842의 필수 검사는 7분 20초 걸렸습니다.

알림

토큰 발급 실패에 대한 알림은 없어서 울린 것이 없습니다. 배포 후 점검에서 CloudTrail을 보다가 찾았습니다.

고친 것

  • Roles Anywhere 프로필의 세션 길이와 mediawiki 역할의 최대 세션을 2시간으로 올렸습니다. infra#1642
  • 세션을 받는 도구가 프로필 한도만큼인 2시간을 요청하게 했습니다. docker-mediawiki#1842에서 고쳐 infra#1648로 10일 0시 15분에 배포했습니다.
